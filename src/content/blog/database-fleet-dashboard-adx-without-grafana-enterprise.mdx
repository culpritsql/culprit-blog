Azure Data Explorer (ADX) is one of my favorite bargains in cloud infrastructure for database telemetry. A small cluster ingests millions of wait, session, and query-interval rows without breaking a sweat, and KQL makes ad-hoc slicing fast.

The catch hits when you want 30 backend engineers to view dashboards without writing KQL.

Teams usually walk into one of two licensing walls:

- **The Grafana ADX tax.** Open-source Grafana ships in Kubernetes everywhere, right up until you install the Azure Data Explorer datasource plugin and discover it is gated behind **Grafana Enterprise** or paid Grafana Cloud seats.
- **The Fabric viewer cliff.** As I broke down in [Microsoft Database Hub vs. Culprit + ADX](/blog/microsoft-database-hub-vs-culprit-adx/), sharing custom Fabric dashboards across an org without an F64 capacity (`~$8,400/month` PAYG) requires a Power BI Pro license for every developer who opens a link.

Even if you pay for either one, neither Grafana nor Power BI knows how to render a 2 MB `.sqlplan` operator tree or diff two execution plans side by side.

## What an estate triage screen actually needs to answer

When someone opens a fleet view during a slowdown, they are not looking for forty sparklines of buffer cache hit ratio. They want four answers in ten seconds:

1. **Which databases have an active incident right now?** (blocking chain, deadlock loop, memory-grant queue, worker starvation, log-rate governance)
2. **Did a recent deploy or statistics refresh flip an execution plan?** (`CulpritChangesV1` regressions)
3. **Is an Elastic Pool or Managed Instance suffering from a noisy neighbor?** (shared-compute grouping attested by native metadata)
4. **Are any collectors stale or missing permissions?** (`collector_failing` / `partial` vs genuinely quiet)

We built `WarehouseFleetReader` over `<Prefix>FleetSummary` in both ADX and [ClickHouse](/blog/azure-data-explorer-vs-clickhouse-database-telemetry/), and surfaced it as the top-level **Estate Triage** grid inside Culprit's `Archives` view. Filter chips (`Needs attention`, `Incidents`, `Changes & regressions`, `High findings`, `Collector health`, `By Elastic Pool / Instance`) and `/` + `j`/`k` keyboard navigation work identically in the desktop app and in the browser:

## Drilling from an Elastic Pool spike into the exact plan flip

Suppose an Elastic Pool starts throttling writes and CPU climbs across six tenant databases. Grouping by `By Elastic Pool / Instance` immediately shows sibling databases waiting on `RESOURCE_GOVERNOR` inside `pool-saas-prod` while `tenant-analytics` accounts for the vCore jump.

Clicking into `tenant-analytics` in `Archives` pulls the sealed `.sqlplan` blobs from Azure Storage, verifies their SHA-256 digests against `CulpritPublishedRangesV1`, and opens the synchronized plan diff right in the browser:

<MssqlElasticPoolDiffEmbed />

Instead of pasting KQL query hashes into SSMS on a jumpbox, every engineer on the incident call can click the operator tree and see that an unindexed rollup on `usage.daily_api_events` fanned out to `DOP = 4` (`1,180 ms` CPU across four workers and `148,200` logical reads), whereas a composite covering index drops it to a single-threaded `Stream Aggregate` + `Index Seek` (`6 ms` CPU, `38` reads).

## Running `culprit-archive-web` behind Entra EasyAuth or OIDC

To share that exact UI across an engineering org with zero per-seat cost, we ship a tiny standalone binary: `culprit-archive-web`.

Run it in Azure Container Apps, App Service (with Entra ID EasyAuth enabled), or Kubernetes behind `oauth2-proxy`:

```sh
culprit-archive-web \
  --config /etc/culprit/evidence-readonly.json \
  --name "Production Fleet" \
  --bind 0.0.0.0:8080 \
  --ui-dist /usr/share/culprit/ui \
  --require-auth-header X-MS-CLIENT-PRINCIPAL-ID
```

`evidence-readonly.json` holds only read-only ADX viewer and Blob reader profiles (Workload Identity or IAM role). It has **no** `connections.toml` and **no** credentials to any SQL Server, PostgreSQL, or MySQL instance.

<Callout title="Strict read-only compile boundary" tone="green">
  <p>
    <code>culprit-archive-web</code> compiles only with the <code>warehouse-adx,evidence-azure,warehouse-clickhouse,evidence-s3</code> read-only feature set. If a user switches time windows mid-query or closes the browser tab, the HTTP handler cancels the underlying Kusto or S3 stream immediately via `CollectionCancellation` so stray tab clicks cannot pile up expensive warehouse scans.

Pair this viewer with [AKS Helm auto-discovery](/blog/monitor-azure-sql-postgres-fleet-aks-adx-helm/) for ingestion and [`culprit-notify`](/blog/sql-blocking-deploy-regression-alerts-slack-teams-pagerduty/) for Slack/PagerDuty links that drop responders straight onto the affected resource window.
